이 문서는 2026년 11월 18일(한국 시간) AI-Talk의 수정 내용을 정리한다.

**이 기록의 출처.** 처음 기록은 커밋이 없는 다른 작업 폴더(회사 PC)에서 쓴 것이다. 이 저장소에는 그 기록을 보고 같은 동작을 다시 구현해 넣었다. 그래서 아래의 "확인한 것"은 두 가지로 나눠 적는다.

- **이 저장소에서 확인**: 이 저장소의 코드로 직접 돌려 본 것. 수치는 [12절](#12-이-저장소에서-확인한-것)에 모았다.

## 1. 모든 화면에 우클릭 전체화면 기능 적용

### 요청

모든 화면에서 마우스 우클릭으로 전체화면을 사용할 수 있도록 개선한다.

### 적용 내용

- 우클릭하면 전체화면으로 전환하고, 전체화면 상태에서 다시 우클릭하면 해제한다.
- 브라우저 기본 동작인 `Esc`로도 전체화면을 해제할 수 있다.
- 새 토론, 페르소나, 지난 토론, 설정, 토론 진행 화면과 접속 코드 입력 화면에 공통으로 적용한다.
- 문서 전체에 캡처 단계의 `contextmenu` 이벤트를 등록해 상단 메뉴, 입력 영역, 팝업에서도 작동하도록 구성했다.
- 전체화면 대상은 `document.documentElement`로 지정해 앱과 문서 본문에 추가되는 팝업·알림을 함께 표시한다.
- 마우스 우클릭의 브라우저 기본 메뉴를 막고, 키보드 메뉴 키 및 `Shift+F10`은 기존 메뉴 동작을 유지하도록 처리했다.
- 전환 중에는 추가 요청을 무시해 연속 우클릭에 따른 중복 전환 요청을 방지한다.
- 전체화면 미지원 시 오류 알림을 표시한다. 전환 실패 시에도 알림을 표시하고 다시 시도할 수 있도록 전환 상태를 해제한다.
- 화면 이동마다 등록하는 대신 앱 시작 시 한 번 등록해 화면을 이동해도 기능을 유지한다.

## 3. 각주 렌더링 수정 및 출처 목록 축소

### 문제와 최종 표시 방식

본문에 마크다운 링크 문법, 긴 인코딩 URL, `turn1view0` 같은 AI 내부 인용 표식이 그대로 표시되고, 발언 아래에 동일 사이트의 출처가 여러 줄로 반복됐다.

사용자 피드백에 따라 도메인 이름과 건수를 접힌 상태에 표시하는 방식도 축소해, 발언에는 **출처 버튼 하나만** 표시한다. 버튼을 누르면 도메인별로 묶인 전체 링크 목록이 펼쳐진다. (버튼의 모양과 위치는 4절에서 다시 바꿨다.)

### 적용 내용

- 본문의 `[이름](URL)` 및 `([이름](URL))` 링크를 클릭 가능한 `[1]`, `[2]` 형태의 번호 각주로 변환했다. 동일 URL은 같은 각주 번호를 재사용한다.
- 링크 라벨과 URL 사이 공백, 긴 인코딩 주소, 쿼리 문자열, URL 내부 괄호 및 선택적 링크 제목을 처리한다.
- 실제 URL과 연결할 수 없는 AI 내부 인용 표식은 본문에서 숨긴다. 임의의 출처 링크를 만들어 연결하지 않는다.
- 스트리밍 중 분할 수신되는 링크와 내부 표식도 처리해 아직 완성되지 않은 링크 주소를 본문에 노출하지 않는다.
- 출처는 URL의 `//`와 다음 `/` 사이에 있는 호스트를 기준으로 묶는다. 동일 URL은 중복을 제거하고, 같은 호스트의 다른 경로는 개별 자료로 보존한다.
- 펼친 목록은 일정 높이를 넘으면 내부 스크롤로 확인한다. 키보드로도 출처를 열고 링크에 접근할 수 있다.
- 발언 카드, 자료 패널의 사전 조사 본문, 출처 패널에 공통 렌더링을 적용했다. 저장된 토론을 다시 볼 때도 동일하게 적용된다.
- 원문과 서버의 저장 데이터는 유지하고 화면 표시를 개선했다. HTTP(S) 출처만 링크로 생성하며, 본문을 HTML로 해석하지 않는다.

이 저장소에서 구현하며 정한 세부:

- 링크 이름이 문장의 일부일 때(예: "[전망 기사](URL)를 보면")는 이름을 글로 남기고 그 뒤에 번호를 붙인다. 이름이 사이트 주소·도메인·번호뿐이거나 링크가 괄호로 싸여 있으면 번호만 남긴다.
- 주소 끝의 조각 표시(`#...`)만 다른 링크는 같은 자료로 본다.

## 4. 각주 번호 통일, 출처 이름 수정 및 아이콘 배치 개선

### 사용자 피드백

- 각주가 발언마다 `[1]`부터 시작해 다른 기사도 같은 번호로 보였다.
- 출처 목록에 `자료 2`, `자료 3`처럼 내용을 알 수 없는 이름이 표시됐다.
- 출처 버튼이 항상 별도 줄에 표시됐다. 공간이 있으면 마지막 문장 옆에 표시하고, `출처` 글자와 `+`도 제거해 아이콘만 남기도록 요청했다.

### 최종 적용 내용

- 토론별 `CitationRegistry`를 도입해 URL별 번호를 토론 전체에서 공유한다. 다른 URL에는 다른 번호를 부여하고, 같은 URL은 발언이 달라도 같은 번호를 사용한다.
- 스트리밍, 최종 발언, 사전 조사 및 출처 패널이 같은 번호 체계를 사용한다. 출처 목록 각 항목에도 본문과 일치하는 번호를 표시한다.
- 토론을 다시 보면 등록 순서를 재구성하며 동일한 기록의 번호를 유지한다. 새 토론은 별도의 번호 체계를 사용한다.
- 실제 기사 제목이 있으면 우선 사용한다. URL·도메인·`자료 N`·`사이트` 등 일반적인 이름만 있으면 한글 인코딩을 풀어 쓴 URL 경로와 쿼리를 표시한다. 임의의 기사 제목을 만들어 붙이지 않는다.
- 뒤늦게 실제 제목이 들어오면 기존 출처 제목을 보완하고 각주 번호는 유지한다.
- 마지막 문장 뒤에 링크 아이콘 버튼(Lucide `link`) 하나를 인라인으로 표시한다. 공간이 부족하면 다음 줄로 자연스럽게 이동한다.
- 아이콘을 누르면 도메인별 목록이 아래에 펼쳐지고, 다시 누르면 접힌다. 버튼에는 `출처 보기`/`출처 접기` 접근성 이름과 펼침 상태를 제공한다.
- 펼친 목록의 긴 제목이나 주소는 한 줄 말줄임으로 표시하며 원래 링크는 유지한다. 마우스를 1초 올리면 앱의 툴팁에 제목과 원래 주소가 나온다.

`apps/web/src/citations.ts`, `apps/web/src/ui/sources.ts`, `apps/web/src/views/stage.ts`, `apps/web/src/styles/app.css`, `apps/web/tests/citations.test.mjs`, `README.md`를 수정하고 [브라우저 검증 페이지](../apps/web/tests/citations.browser.html)를 추가했다.

## 5. 출처 이름을 실제 브라우저 탭 제목으로 표시

### 요청 및 적용 내용

URL 경로를 풀어 쓴 이름 대신 링크를 열었을 때 브라우저 탭에 표시되는 페이지 제목을 사용하도록 요청했다.

- 서버의 `/api/source-titles` API가 출처 페이지 HTML의 `<title>`을 직접 조회한다. 한국어 인코딩과 HTML 엔티티를 처리하고 제목의 실제 문구와 사이트 이름을 유지한다.
- 출처 목록을 펼칠 때 제목을 비동기로 불러와 목록 이름과 툴팁을 갱신한다. 출처 패널에서도 같은 방식으로 제목을 확인한다.
- 접힌 발언 출처는 미리 조회하지 않는다. 같은 URL의 진행 중인 요청과 결과를 캐시로 공유해 목록을 다시 열어도 반복 조회하지 않는다.
- 실제 탭 제목은 기존 검색 결과 제목보다 우선한다. 제목만 갱신하고 각주 번호와 원래 링크는 유지한다.
- 페이지 접근 실패, 응답 지연, HTML이 아닌 자료 또는 `<title>`이 없는 페이지는 기존 제목·주소 표시를 유지한다. JavaScript가 페이지를 연 뒤 바꾸는 제목은 별도로 실행하지 않는다.
- 조회는 HTTP(S) 공개 웹 주소에 제한하고 리디렉션 목적지도 확인한다. 이 PC나 내부망을 가리키는 주소는 받지 않는다. TLS 인증서 검증은 유지한다.
- 한 번에 최대 20개 URL, 서버 동시 조회 4개, 페이지당 총 조회 시간 8초 및 다운로드 512KiB 제한을 적용했다. 성공 결과는 24시간, 실패 결과는 5분 캐시하며 캐시는 최대 512개 URL을 유지한다.
- LLM 호출이나 신규 패키지 설치 없이 기존 `httpx`와 `beautifulsoup4`로 구현했다.

원래 기록에는 실제 공개 뉴스룸 기사 1건을 HTTP로 조회해 탭 제목 추출에 성공했다고 적혀 있다. 이 저장소에서는 가짜 웹(시험용 전송 계층)으로만 확인했고 실제 사이트는 조회하지 않았다.

## 6. P-GPT 설정과 연결 안내 정리

- API 키는 `PGPT_API_KEY` → `API_KEY`, 인증에 사용할 코드는 `PGPT_SYSTEM_CODE` → `PGPT_EMPNO` → `EMPLOYEE_NO` 순서로 찾는다. 각 별칭 묶음은 `.env` 전체를 먼저 확인한 뒤 Windows 환경변수를 확인한다. 빈 값은 다음 후보로 넘어간다.
- `COMPANY_CODE`의 기본값은 `30`이다. 실제 비밀값은 예제·문서에 기록하지 않는다.
- 기본 연결 주소는 프로바이더에 정의된 값을 사용하고, 설정한 주소는 `/v1` 기준으로 정규화한다. `PGPT_WEB_SEARCH_TOOL`로 검색 도구 이름을 지정할 수 있다.
- 프로바이더 선택은 시험용 `AITALK_FORCE_PROVIDER`, 설정 화면에 저장된 선택, `.env` 설정 순으로 적용한다. 설정 화면은 키 값 대신 연결 준비 상태와 필요한 변수 이름을 안내한다.
- OpenAI Python SDK 요구 버전을 `openai>=3.37.0,<4`로 명시한다. 패키지를 새로 설치하지는 않았다. `installer.bat`을 다시 실행하면 이 범위로 맞춰진다.

## 7. P-GPT 상태 유지·웹 검색·문맥 복구 보완

### 최종 동작

- 발언은 `store=True`와 `previous_response_id`로 이어 붙인다. 연출자 판단은 마지막 발언에서 `store=False`로 분기하고 검색 도구를 넣지 않아 판단 내용이 토론 줄기에 남지 않게 한다.
- 검색 도구는 `web_search`를 우선하고 도구 이름이 거절될 때 `web_search_preview`로 재시도한다. 검색어 배열, 페이지 열기·본문 찾기, 검색 결과 및 인용 출처를 수집하고 `max_tool_calls`로 호출 수를 제한한다.
- 자동 압축은 `context_management`로 요청한다. 스트리밍 이벤트와 최종 출력 양쪽의 압축 항목을 확인하고 검색·출처 항목은 중복 수집하지 않는다.
- 자동 압축을 사용할 수 없거나 문맥 초과가 발생하면 명시적 `/responses/compact`를 시도한다. 사용할 수 없으면 오래된 발언을 묶음별 누적 요약으로 바꿔 새 줄기를 만든다. 최근 발언과 앱의 원문 기록은 유지한다.
- 명시적 압축에 권한 거절이 발생하면 해당 프로바이더 인스턴스에서 반복 시도를 생략한다. 요약이 실패하거나 비어 있으면 기존 원문과 문맥 복구 자료를 지우지 않는다.
- 이전 응답 ID를 찾지 못하면 앱이 보관한 기록을 다시 입력해 복구한다. 끊긴 발언은 화면에 확정된 부분만 문맥에 남기며, 압축 뒤 필요한 공통 규칙을 다시 전달한다.
- 스트리밍이 정상 완료되지 않았으면 성공한 발언으로 확정하지 않는다. 이미 글자를 내보낸 요청은 오류 후 그대로 재전송하지 않아 발언 중복을 방지한다. 오류 안내에는 API 응답의 비밀값을 노출하지 않는다.

### 검증 범위와 재현

원래 기록에는 11월 18일 회사 OA망에서 상태 유지, 판단 분리, 실제 `web_search`와 출처 반환, 실제 자동 압축과 이후 기억 복원, 요약 복구를 검증했고, 명시적 압축은 당시 검증 계정에서 HTTP 403이었다고 적혀 있다. 이 결과를 모든 모델·계정의 지원 여부로 확대하지 않는다. **이 저장소의 코드는 그 기록을 보고 다시 쓴 것이라, 실제 P-GPT로는 아직 한 번도 돌려 보지 않았다.** 회사에서 아래 스크립트를 `--execute`로 다시 돌려 확인해야 한다.

[문맥 회귀 테스트](../apps/server/tests/test_pgpt_context.py)는 응답 만료, 문맥 초과, 압축 거절, 요약 실패, 끊긴 발언, 검색 중복 수집 및 미완료 스트림을 가상 API로 확인한다. [check_pgpt_context.py](../scripts/check_pgpt_context.py)는 `--execute` 없이 검증 범위만 표시하고, `--execute`를 붙이면 실제 P-GPT 호출을 수행한다.

```powershell
python scripts/check_pgpt_context.py
# 실제 P-GPT 검증을 별도로 수행할 때
python scripts/check_pgpt_context.py --execute
```

구현: [pgpt.py](../apps/server/aitalk/providers/pgpt.py). 상세 설계: [설계 문서 8절](design.md#8-문맥-관리와-캐시).

## 8. Windows 실행기의 즉시 하드 리셋과 실행 창 개선

- `ai-talk.bat`는 [launch_aitalk.py](../scripts/launch_aitalk.py)를 통해 서버를 별도 프로세스로 실행한다. 실행 창에 포커스를 두고 `R`, `r`, 한글 입력의 `ㄱ`을 누르면 Enter 없이 하드 리셋한다.
- 문자뿐 아니라 물리 R 키도 판별하고, 키를 누르고 있는 동안에는 한 번만 처리한다. 실행기가 콘솔 입력을 읽고 서버에는 표준 입력을 넘기지 않는다.
- 리셋은 진행 중 토론과 서버·빌드 자식 프로세스를 종료한 뒤 새 Python 프로세스로 설정과 코드를 다시 읽는다. 저장된 SQLite 기록과 페르소나는 유지하며 브라우저는 새로고침해야 한다.
- 시작·재시작 전에 설정 포트의 TCP 리스너와 자식 프로세스를 정리한다. **다른 프로그램이 같은 포트를 사용 중이어도 종료 대상이 된다.** 겹치면 `.env`의 `AITALK_PORT`를 바꿔야 한다.
- 코드 오류로 서버가 종료돼도 콘솔 입력을 사용할 수 있으면 `R`로 재시도할 수 있다. `Ctrl+C`는 실행기와 서버를 종료한다. 브라우저 자동 열기는 첫 실행에만 수행한다.
- [console.py](../apps/server/aitalk/console.py)는 ASCII 로고, 연결 준비 상태, 이 PC·다른 PC 접속 주소, 접속 코드 설정 여부, 종료·재시작 키를 표시한다. 키와 접속 코드 값은 표시하지 않는다.

회귀 검사: [test_launcher.py](../apps/server/tests/test_launcher.py), [test_launcher_windows.py](../apps/server/tests/test_launcher_windows.py). 뒤의 것은 시험이 띄운 프로세스와 임시 포트만 건드린다.

## 9. 진행 요청을 주최자 지시로 처리

[설계 문서 20절](design.md#20-진행-요청은-반드시-따르는-지시)의 변경이다. 이 저장소에는 이미 들어 있던 내용이라 이번에 고친 코드는 없다.

- 진행 요청은 `【주최자 지시】`, 청중 질문은 `【청중】`으로 구분한다. 공통 규칙과 발언 지시문은 진행 요청을 참고 의견으로 평가하거나 넘기지 않고 실제 수행하도록 안내한다.
- 지시가 들어오면 미리 생성한 발언을 버리고 진행자가 먼저 전달·수행한다. 진행자가 없으면 오래 조용했던 참가자가 먼저 수행한다.
- 엔진이 참가자별 미수행 지시를 기억하고 다음 발언에 수행 지시와 발언자 선택 가산점을 적용한다. 청중 질문은 전원 수행 지시로 남기지 않는다.
- 일시정지 중 요청이나 질문을 보내면 토론을 이어 간다.

지시 준수는 프롬프트와 엔진으로 유도하는 동작이며 모델 응답 전체에 대한 보장을 뜻하지 않는다. 관련 구현: [prompts.py](../apps/server/aitalk/prompts.py), [engine.py](../apps/server/aitalk/engine.py).

## 10. 회의록 대기 카드와 화면 보완

- 회의록 작성 중 펜 아이콘·채워지는 줄·초 단위 경과 시간을 보여 준다. 단계별 진행률을 계산할 수 없는 호출이므로 완료 비율을 표시하지 않는다.
- 완료하면 회의록으로 교체하고 실패하면 카드가 사라지며 경고를 표시한다. 다시 쓰는 동안 기존 회의록은 유지한다. 움직임 줄이기 설정에서는 애니메이션을 멈추고 경과 시간은 계속 표시한다.
- 조작 줄 버튼 묶음이 두 줄로 접히지 않도록 하고 총 비용 상세를 한 줄 두 칸으로 배치한다.
- [index.html](../apps/web/index.html)의 루트에 `spellcheck="false"`를 설정해 브라우저 기본 맞춤법 검사를 비활성화한다. 초기 테마는 저장된 값을 화면을 그리기 전에 적용한다.

이 저장소에는 맞춤법 검사 비활성화만 새로 넣었다. 나머지는 이미 들어 있었다. 관련 구현: [stage.ts](../apps/web/src/views/stage.ts), [app.css](../apps/web/src/styles/app.css). 대기 카드 상세: [설계 문서 21절](design.md#21-회의록을-쓰는-동안-보이는-카드).

확인하지 못한 것:

- **P-GPT 실제 호출 전부.** 문맥 복구, 검색 수집, 압축은 가상 API로만 보았다.
- **실제 전체화면 전환.** 검증 페이지는 `requestFullscreen`을 가짜로 바꿔 이벤트 처리만 보았다. 실제 창이 전체화면이 되는 것과 `Esc` 해제는 눈으로 보지 않았다.
- **실행 창에서 실제로 `R`을 누르는 것.** 키 판별과 다시 켜기 흐름은 가짜 입력으로, 포트 정리는 시험용 프로세스로 보았다. 실제 콘솔에서 한글 입력 상태의 `ㄱ`이 어떤 키 값으로 오는지는 회사 PC에서 확인이 필요하다.
- **밝은 테마에서의 각주·출처 모양.** 색은 기존 테마 변수를 쓰지만 화면으로는 어두운 테마만 보았다.
